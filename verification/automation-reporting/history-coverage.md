# Admitted-history publication lifecycle mapping

This new bounded model is separate from the four existing TLC graphs and 25 paired model/source witnesses. Those pins, graphs and assumptions remain unchanged. The lifecycle model adds no TLC claim.

Run `node verification/automation-reporting/history-model.mjs` and `node --test test/automation-reporting-history.test.mjs`. The explicit transition graph exhausts 950 states and 1737 edges with one owner, two competing callbacks, two source records, two generations at most one crash, and one explicit readback refresh. A generation includes its full source objects plus one immutable inventory. Correct no-effect/unknown creates and pointer intents can terminate uncertain. The implementation bounds read refresh to twenty attempts per exact object readback; the model abstracts this to one refresh to check safety, not arbitrary retry convergence. No liveness is asserted. Baseline and restored graphs must agree. Five model mutations must return their named violated invariant and finite path.

The model abstracts atomic immutable intent publication, exact-ID persistence, matching metadata/full raw bytes, and owner generation handoff into distinct actions. Model upload effects and retained IDs are separate, so crashes before and after effect can become uncertain. Another callback loses the intent claim. A recovered known ID advances only through metadata and raw checks. Failed metadata/raw responses enter a retained read-failed state. Production refresh reacquires both metadata and complete raw bytes. An explicit known-ID refresh can retry without deleting failure evidence or permitting another upload. Generation closure precedes anchor advancement. Crashed pointer updates reconcile the exact ID without another update. Persisted pointer intent and unique dispatch are separate model actions. A crash between them remains unresolved. RPC response state and actual effect are independent. Pending effects can land at any later phase, including after a later generation returns. An exact old read cannot prove quiescence, so it enters pointer-unresolved and can only refresh the exact-ID read. The source additionally serializes per-anchor batches in one private state directory; different state stores are outside the single-owner assumption.

The actual fresh-process boundary drive stops a child at every emitted durable checkpoint, including prepared bytes, committed hard links, batch, owner claim, intent, returned remote effect, retained response and both closures. A separately retained synthetic exact provider response permits recovery after lost upload responses. No returned ID means uncertain and no repeated create. The retained report lists every cutoff and result. Ordinary Node process exit at these checkpoints does not establish arbitrary-instruction termination, filesystem power-loss durability or authenticated provider behavior.

Actual source controls cover all canonical TARGET revisions/conflicts/attempts/receipt bytes, report nulls, original clocks, concurrent appends, malformed metadata, incomplete raw materialization, wrong IDs/parents/MIME/hash/length, raw credential refusal, repeated responses, competing batches, failed pointer updates, later external pointer forks, generation lineage, missing history, checkpoint regression, generation-zero bootstrap and a frozen standalone outside the repository. Existing capture tests retain whole-history projection and unchanged original-clock semantics.

Assumptions include collision-free SHA-256, complete declared producer admission, immutable canonical source files, trusted cooperating owner and runtime adapter, exact bounded authenticated file-reference materialization, ordinary private directories and atomic same-filesystem hard links. Normalized fields and retained provider responses remain reported evidence, not authentication by this module. The adapter's reference provenance cannot be established by a caller-supplied flag. Hidden/unregistered writers, independent stores, external multiwriter updates, global latest, CAS, arbitrary secrecy, provider exactly-once behavior, recurring invocation, deployment, actual work and user delivery remain excluded.

The source owner retains fail-first evidence against old source, failed exploratory tests and successful focused results under ignored `.local/consumer-evidence/`. Source pins and aggregate checks remain parent-owned review gates. Updating this mapping does not refresh a reviewed source digest.

Import errors, syntax errors and unrelated exceptions cannot satisfy this oracle control.

Every publication permission reprojects all other claimed owner generations from their current retained journals. Historical pointer closure cannot override a later contradictory upload receipt, including after a successor claim or across older ancestors. Matching late receipts preserve valid handoff. Six behavioral controls cover matching and conflicting receipts before handoff, after successor claim, and after an older ancestor has a published successor; old journal bytes remain unchanged and blocked successors perform no new adapter effects. This current-evidence guard is outside the unchanged finite lifecycle graph.
