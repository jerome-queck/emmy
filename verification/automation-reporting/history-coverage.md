# Admitted-history publication lifecycle mapping

This new bounded model is separate from the four existing TLC graphs and 25 paired model/source witnesses. Those pins, graphs and assumptions remain unchanged. The lifecycle model adds no TLC claim.

Run `node verification/automation-reporting/history-model.mjs` and `node --test test/automation-reporting-history.test.mjs`. The explicit transition graph exhausts 406 states and 649 edges with one owner, two competing callbacks, two source records, two generations at most one crash, and one explicit readback refresh. A generation includes its full source objects plus one immutable inventory. Correct no-effect/unknown creates can terminate uncertain. The implementation bounds read refresh to twenty attempts per exact object readback; the model abstracts this to one refresh to check safety, not arbitrary retry convergence. No liveness is asserted. Baseline and restored graphs must agree. Four model mutations must return their named violated invariant and finite path.

Two additional copied-source pairs remove metadata-before-fetch or checkpoint lineage matching. Their concrete witnesses return a raw-fetch action for an academic-parent metadata mismatch or accept a regressed checkpoint. Missing mutation anchors, import errors and unexpected exceptions are failures. A mutant counts only when its designated concrete wrong output returns. Each pair runs baseline, copied production mutation and an unchanged restored copy. Full source/output evidence remains in ignored `history-source-pairs.json`.

The model abstracts atomic immutable intent publication, exact-ID persistence, matching metadata/full raw bytes, and owner generation handoff into distinct actions. Model upload effects and retained IDs are separate, so crashes before and after effect can become uncertain. Another callback loses the intent claim. A recovered known ID advances only through metadata and raw checks. Failed metadata/raw responses enter a retained read-failed state. Production refresh reacquires both metadata and complete raw bytes. An explicit known-ID refresh can retry without deleting failure evidence or permitting another upload. Generation closure precedes anchor advancement. Crashed pointer updates reconcile known ID before another update. The source additionally serializes per-anchor batches in one private state directory; different state stores are outside the single-owner assumption.

The actual fresh-process boundary drive stops a child at every emitted durable checkpoint, including prepared bytes, committed hard links, batch, owner claim, intent, returned remote effect, retained response and both closures. A separately retained synthetic exact provider response permits recovery after lost upload responses. No returned ID means uncertain and no repeated create. The retained report lists every cutoff and result. Ordinary Node process exit at these checkpoints does not establish arbitrary-instruction termination, filesystem power-loss durability or authenticated provider behavior.

Actual source controls cover all canonical TARGET revisions/conflicts/attempts/receipt bytes, report nulls, original clocks, concurrent appends, malformed metadata, incomplete raw materialization, wrong IDs/parents/MIME/hash/length, raw credential refusal, repeated responses, competing batches, failed pointer updates, later external pointer forks, generation lineage, missing history, checkpoint regression, generation-zero bootstrap and a frozen standalone outside the repository. Existing capture tests retain whole-history projection and unchanged original-clock semantics.

Assumptions include collision-free SHA-256, complete declared producer admission, immutable canonical source files, trusted cooperating owner and runtime adapter, exact bounded authenticated file-reference materialization, ordinary private directories and atomic same-filesystem hard links. Normalized fields and retained provider responses remain reported evidence, not authentication by this module. The adapter's reference provenance cannot be established by a caller-supplied flag. Hidden/unregistered writers, independent stores, external multiwriter updates, global latest, CAS, arbitrary secrecy, provider exactly-once behavior, recurring invocation, deployment, actual work and user delivery remain excluded.

The source owner retains fail-first evidence against old source, failed exploratory tests and successful focused results under ignored `.local/consumer-evidence/`. Source pins and aggregate checks remain parent-owned review gates. Updating this mapping does not refresh a reviewed source digest.

The fresh CLI read-retry and worker restart controls recover a metadata exception and a truncated raw response within the same generation, with every prior event byte unchanged. Unknown upload retries remain forbidden. `materializePublicationUpload` verifies exact immutable local payload bytes and `next` exposes supported tool arguments; actual runtime file-reference registration remains parent-owned. Run `node verification/automation-reporting/history-fixture.mjs` after building to retain a synthetic two-generation cloud packet and old checkpoint. It performs zero provider calls.

The initial explicit read-retry abstraction exhausted 446 states and 689 edges. It resumed a failed raw read from the raw-check stage. Final production retry restarts the metadata/raw epoch together, so the refined model resumes both read failures from the known-ID stage. This removes unreachable retained-metadata retry combinations, yielding 406 states and 649 edges. The four invariants, owner/record/generation/crash/retry bounds and four counterexample obligations are unchanged. Earlier model output remains retained as development evidence.
