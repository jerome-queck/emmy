---
name: morning-collect
description: Collect morning source evidence or recover read-only accounting failures using private raw-response files and the existing morning run.
---

Use the owning runtime's available tool discovery and returned documentation. The local Mac and parent cloud runtime have different tools. Choose supported connectors or visible UI; this skill supplies no app adapter or additional access.

1. Recover the existing run and exact owner/account/source scope. Choose `ordinary-authorized` for separately authorized reads outside fleet admission, or `admitted` for an existing actual job/ticket. A known-ended read-only counter failure does not establish app inaccessibility. Actual tool denial stops that scope; uncertain mutation holds dependent effects.
2. Begin a private capture directory with `node scripts/collect-morning.mjs begin DIRECTORY CONFIG_JSON`. Config: `runId`, `sourceId`, exact `scope`, existing `ownerRef`, `provenance`, `jobKey`, `ticket`; ordinary uses null job/ticket. Add current `generation` only for a selected-ID refresh.
3. After each supported read, persist or emit its raw response through the actual runtime's supported file/output API **before** parsing or counting. Then supply that raw file to `collect DIRECTORY CAPTURE_JSON RAW_FILE`. The helper copies supplied bytes first; it does not call or protect app APIs. Capture metadata: sequential `attempt` (ordinary1–62; admitted1–32), original `observedAt`, `capturedAt`, `outcome:"returned"`. For a lost response use `outcome:"lost"`, attributable `reason`, no raw file. A real denial uses `outcome:"denied"`; retain it and stop that scope. Exclude login, MFA and secret-bearing screens.
4. Outlook inventory: inspect both Focused and Other, pagination and completeness. Verify rendered row selectors live before reuse; use stable conversation IDs, sender/subject/date tooltips and visible unread actions. Scroll using returned list bounds with overlapping captures; reverse passes recover virtualization omissions. Bottom alone does not prove completeness: deduplicate IDs and reconcile both category set sizes, then final folder/unread/category counts with no item selected. Keep conversation counts, message counts and folder counts separate. One category alone is partial. Inspect unread content only through a state-preserving supported route; retain unsafe inspection as held. Preserve original source time separately from fetch time.
5. Finish once: `finish DIRECTORY DETAILS_JSON`. Details: `attempts`, `coverage:{complete,gaps}`, `paginationComplete`, `cached`, exact `resourceIds`, `messageIds`, `window` (full Singapore day for calendar/Tasks; null for mail). Missing response/Other/page/count stays an explicit gap. Known bytes are a lower bound when any response is lost; budget compliance remains unverified. Count serialized JSON UTF8 bytes after raw persistence; keep artifact size separate (pretty whitespace/newline differs). A counter/parse failure retains original metadata, raw bytes and unknown measurement for a finishable partial packet. Bounds:62ordinary captures (32admitted) and1MiBknown serialized bytes per collection; split subsequent reads into another private collection.
6. Inspect `intake.json`: one existing morning `source` command, raw/packet evidence paths, explicit provenance. Supply optional `envelope:{responsibilityId,expectedHead,authorityEvidence:[{sourceRef,path}]}` in finish details on the receiving host. Finish hashes all evidence and writes directly usable `envelope.json`; submit once with the existing fleet CLI. Capture paths are relative for parent-owned transfer, with original timestamps intact. The helper supplies no transport/bridge. Refresh the head before a conflicting journal write. Ordinary intake creates no completed/admitted ticket. Admitted intake still needs its actual completed job and exact receipt. A selected-ID collection covers those IDs only and never repairs global gaps. Review fresh full-thread/before evidence before cleanup; changed plans require verified edit of the original native brief. Use compact body for human delivery and retain diagnostics privately.

The helper writes files only. Native reads, send/edit/move effects and same-ID readbacks remain the authorized operator's work. Unknown send/edit/action is inspected and resolved before dependent effects; verified moves remain terminal.
