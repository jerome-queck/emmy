# Local assurance contract

Run `node verification/local-assurance/check.mjs` with Node 24 or later, existing Java 21 and the existing pinned TLC jar. No installation or download is performed. Run `node scripts/verify-behavior.mjs --focus assurance` for actual package/CLI and filesystem controls. Full `npm run check` separately executes the complete production suite.

Read every TLC result with `/statechart` by name. The report names each generated `Assurance.tla`, config, graph, view, raw TLC output and actual-code replay. Use the installed skill's current instructions; its invocation is not copied here. Preserve every failed result. `--development` skips reviewed pins and cannot satisfy aggregate acceptance.

## Properties and harm

| Rule | Promise and harm | Production mapping | Required copied-source break |
| --- | --- | --- | --- |
| `PassedComplete` | Acceptance requires every fixed suite. Early success could hide untested source. | `assuranceTransition` final completed-prefix comparison and `assurancePlan` | `coverage` accepts after one suite. |
| `PassedClean` | Acceptance requires the exact ordered suite/result, unchanged context, zero exit, no signal/spawn error and verified output. A broken guard could accept stale, failed or unrelated evidence. | Context comparison, start/result identity guards and finish result/output guards in `assuranceTransition` | `context`, `suite-order`, `result-id`, `exit`, `output`. |
| `RefusalTerminal` | A refused run stays refused. Otherwise later input could erase its original failure. | Initial refused-phase return in `assuranceTransition` | `resurrection` reopens a refused state. |

The graph is generated by calling the actual production reducer. Independent graph facts record input violations and successful-prefix length; TLC properties compare those raw facts with the resulting phase. It is not a hand-written model of the acceptance function. Each counterexample is replayed against the actual mutated module, event by event, with state equality and intended-harm assertions. Syntax/import errors and unrelated exceptions never count as killed mutations. Unchanged production runs again after mutations.

## Coverage and atomicity

Sync commit `55cad1b31225cbf014c3b22f18223a6f817c2fcd` is recorded by full immutable ID in [coverage.json](../../../verification/local-assurance/coverage.json), together with exact file digests and function mapping. The runner compares covered working bytes with that commit and checks verification-file hashes. The skill and [generated chart](../../../verification/local-assurance/chart.mmd) are also pinned. Hashing the local adapter and CLI does not turn their I/O behavior into a TLC proof.

`src/assurance.mjs` owns `beginAssurance`, `assuranceTransition` and the fixed seventeen-suite plan. A transition is one synchronous JavaScript call. `src/local-assurance.mjs` owns separate Git/filesystem observations, process execution, output retention and receipt assessment. `scripts/check.mjs` is the aggregate ingress; `scripts/agent.mjs` exposes read-only receipt assessment. The Markdown suite receives an exact working-tree inventory captured through a private index. Before binding, a missing default TLC cache uses the publication verifier's existing pinned acquisition; corrupt caches and missing overrides refuse. Tool preparation is not model verification. Suite output, receipts and formal results remain under `.local/verification/`, already uploaded by the hosted workflow. No real-index staging or new canonical journal record is involved.

The finite graph has one run, the complete production plan, exact-next and wrong suite identities, two symbolic context digests and twelve event classes. They cover start, wrong start, changed-context start, successful finish, failed exit, wrong result ID, changed-context finish, signal, spawn error, invalid output, unchanged inspection and changed inspection. All reachable products under this domain are explored. Output bytes reduce to a verified/unverified Boolean; context reduces to equality. The chart omits transitions that remain within one displayed label, including repeated checks and terminal inspections. It does not omit graph exploration.

Assume trusted checker code, collision-free hashes, honest acquired process/context facts and ordinary cooperating filesystem behavior. The graph proves no atomic source snapshot, all-instruction crash recovery, descendant cleanup, arbitrary event payloads, unbounded retries, tool/OS authenticity, reviewer independence, provider action, native host identity, installation or future invocation. A consistently fabricated/rehashed receipt remains unauthenticated. Empirical drives verify the declared I/O boundary separately.

## Maintain the contract

Before changing pins, run the old check and retain its result. Read every covered diff from the sync commit, including moved/new callers and the fixed suite. Classify an intentional promise change, verification drift and a product bug separately. Update graph facts from actual code before rerunning; never weaken an invariant to hide a bug.

Run all seven intended real-source mutations and the restored baseline. Read every TLC result with `/statechart`; replay reported paths against actual code. Follow the empirical driver and inspect retained output after teardown. Then commit reviewed source, update full sync commit/digests separately, and rerun with the reviewed-source gate enabled. Leave pins unchanged when blocked. Independent source review remains a separate integration gate.
