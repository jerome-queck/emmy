# Automation reporting contract

Run from the repository root:

```sh
node scripts/verify-automation-reporting.mjs
```

Requires Node 24 and Java 21. `EMMY_JAVA_BIN` selects Java; `EMMY_TLC_JAR` selects a jar whose SHA256 must match the existing publication verifier's pinned official TLA+ tools 1.7.4 release. Missing jars download only from that pinned release. No account, provider or API key is used.

Read `verification/automation-reporting/coverage.json`, `AutomationReporting.tla` and the actual production functions named in the mapping before interpreting a pass. Read results with the installed pstack `/statechart` skill. Its current location and invocation belong to that installed skill, not this contract.

The promise: readers never accept partial, corrupt, reference-incomplete or conflicting captured records as current, and producer records never authenticate execution or delivery. A false clean status can hide a missed run or failed delivery. Immutable publisher records remain complete and returned publications remain visible across retries.

The bounded model has two writers publishing distinct conflicting revision-one successors of one retained predecessor, one reader, one corrupt sync input, a stale/fresh captured input flag and one crash/retry per writer. Pending partial writes, completed writes, atomic hard link, reply, crash, retry, list capture and classification are separate actions. A scan can capture any subset and separately claim complete or incomplete. This overapproximates concurrent snapshots; it is not a globally atomic snapshot guarantee. `bad` abstracts corrupt or rejected synced bytes. The current captured set does not change when later writes arrive.

`PublishedComplete` checks canonical producer bytes are committed, `CompletedSurvive` checks returned records persist, `AcceptedSafe` requires complete valid conflict-free captured inputs and `NoFalseAuthority` prohibits independently authenticated status. `StaleVisible` keeps old supplied records visibly stale, while preserving their historical reported execution. `TypeOK` checks domains. The authority flag represents independent authentication, not producer-reported verified state.

Assume collision-free digests, completed writes contain exact intended bytes, atomic same-filesystem hard links, ordinary immutable files, unique pending names and no external deletion or modification of already-published producer records. Corrupt sync is explicitly separate untrusted input. Metadata checks are silent under these assumptions. No liveness, power-loss durability, arbitrary input-size proof, hostile OS ownership protection, authenticated telemetry, native execution, provider calls, schedule firing, delivery, deployment or cloud adoption follows.

The command must report three complete baseline and restored state graphs, all seven original model counterexamples and source witnesses, plus twelve expectation model counterexamples and paired copied-source witnesses. A parse error, missing mutation anchor, unrelated thrown exception, source-drift refusal or missing witness is failure, never a detected mutant. Evidence stays under ignored `.local/automation-reporting-model/`.

Before updating coverage, retain the stale-byte refusal; read every covered source diff from its recorded review basis and review every await, validation gate and projection field. Keep atomic model steps aligned with actual source. Do not weaken an invariant to match a bug. Replay counterexamples against actual copied source, then run unchanged restored baselines. Refresh source and verification digests only after reviewing the exact bytes; advance the source commit only after independently reviewing the committed covered diff. The initial implementation can name a base commit and exact uncommitted source digests explicitly; it must never claim those bytes exist at that base commit. Use `pstack:maintain-formal-verification-skill` after later changes.

The paired copied-source witnesses cover canonical open-before-write, suppressed completeness/conflict/predecessor validity, producer assurance escalation and hidden staleness. Corrupt filesystem scans exercise the same completeness refusal, and an actual stopped baseline writer restarts then retries identically. Missing occurrence correlations, receipt causal clocks, telemetry schema, native ownership, exhaustive parser validation, list pagination and dashboard presentation remain separate behavioral checks. A pending orphan can remain after a crash; no model or baseline promises cleanup or automatic recovery.


`RunTransitions.tla` is a separate small transition model. Its supplied execution states are unknown/running/blocked/pending-approval/completed/failed/skipped. An expected slot without a run never reports success. Terminal completed/failed/skipped states cannot change execution on a same-key revision. A verified receipt cannot regress on a same-key revision. Explicit producer creation can supply any run state; it remains reported. New-key retries, receipt subject changes and occurrence binding are production guards outside this model's enumeration. Three actual-source mutants infer completed from a missing slot, remove the terminal execution guard and remove the receipt stability guard. Baseline actual publication refuses both regressions; mutants publish the invalid successor. Equal-terminal evidence attachment is allowed. No progress, retry completion or externally true terminal state follows.

Run timing is optional producer-supplied evidence. `actualTiming` preserves supplied timing or explicit nulls; it never substitutes recordedAt for actual start, heartbeat or end. Timing observation age feeds the existing stale flag. The copied-source stale mutant is also checked against an old timing observation under a fresh wrapper. Timestamp ordering and schema validation remain behavioral checks outside TLC; no actual process liveness or measured heartbeat truth is proved.

The copied-source dependency closure includes reporting-privacy.mjs. Known credential-pattern rejection runs synchronously before kind validation and adds no publication await or modeled transition. Its lexical coverage and cloud export selector are behavioral controls, outside TLC. A pass proves neither arbitrary secrecy nor safe content for every provider; local paths can remain valid private reporting data.

Generic automation-outcome reports and existing improvement reports share the same immutable run envelope. The copied-source dependency closure includes automation-reporting-outcome.mjs and checks an explicitly unavailable generic report with null sourceWindow. Generic shape validation, report availability semantics and report producer truth are behavioral controls outside TLC. Neither report variant adds an I/O await or changes the modeled run/receipt transition guards.

The current committed source pin is recorded in coverage.json as reviewed-commit. The runner checks current source hashes against those exact committed bytes. Concise status summaries, paginated inspect detail and namespace/automation filters are read projections outside TLC. Validation/dry-run preflight namespace and predecessor reads are separate behavioral controls; the modeled publisher returns through its unchanged publication path. The copied-source corrupt-scan witness uses inspect to retain run detail.

The copied publisher checkpoint retains its opened handle in a live timer closure and forces garbage collection before exposing the complete marker. The reader checks that handle descriptor and exact child identity, then still requires owned SIGKILL. The retained Node 26 GC exception was a harness lifetime failure, never an intended mutant. Primary witness failures, cleanup status and evidence-write failures are retained separately and included together in the reported failure. Models and invariants remain unchanged. Sanitized transport, cloud preparation and managed upkeep repair have separate executable/fault controls; they are outside this TLC mapping. In particular, APFS filename/namespace aliases and repair unlink safety are runtime-tested under explicit cooperating-writer/immutable-byte assumptions, not proved by this publication model.

`ExpectationProjection.tla` separately models one immutable expected slot, its exact original registration dependency, one current registration leaf, one candidate producer run and one captured read. `Capture` chooses caller control-role match, registration owner and target match, valid original dependency, complete/usable capture, source freshness, changed/disabled configuration, edit-effective ordering, candidate usability, grace ordering and absent/exact-bound/other-slot/manual run kinds. `ReadProjection` performs the pure production projection. Its baseline exhausts 16,385 states at depth 3. It neither dispatches work nor advances an execution state.

`AuthoritySafe`, `ConfiguredSlotSafe`, `TargetSafe`, `OwnerSafe`, `DependencySafe` and `CompleteSafe` require the configured control role, configured slot and usable exact dependencies before a non-unknown classification. The role is caller configuration. An actor string in a record grants no authority. `WithdrawalSafe` withdraws changed or disabled slots at or after the latest effective observation. Earlier slots under changed history remain unknown. `FreshSafe` forbids expected/observed/observation-gap under stale registration evidence. `ExactSlotSafe` and `ManualExcluded` prohibit a different nominal slot or manual run from matching. Exact binding comes from the validated producer own occurrence. An early report-null running run can be observed while its report remains missing. `NeverInferSuccess` and `GraceNeverFailure` retain execution not-inferred even beyond observation grace. A real supplied running run remains running after grace.

The runner retains the original two models, seven model mutants and seven source witnesses. It adds this third baseline/restored graph and twelve paired model/source mutants. `expectations-drive.mjs` copies the full production owner and its exact dependency closure, mutates only named projection guards, and calls the real aggregate with schema-valid records. Every mutant must exhibit its designated concrete result. A missing anchor, import error, schema exception or other failure cannot count. Restored witnesses execute a fresh unchanged copy. Positive controls include grace equality, source-age equality and one millisecond beyond, disabled and edited schedules, historical edit uncertainty, missing or conflicted registration dependencies, unbound candidates, unusable bound candidates, early report-null running observations, a fresh observation with unchanged fingerprint, running after grace, strict expectation creation before the slot and registration fingerprint rejection.

The production mapping includes `projectControlExpectations`, `validateControlRecord`, `registrationFingerprint` and `expandExpectedSlots`. Boolean configured-slot/dependency/usable predicates abstract validated schema, exact digest lookup, current-leaf selection, conflict freedom and recurrence membership. The paired source controls exercise these named cases; TLC does not enumerate all recurrence strings, digest collisions, parser inputs or arbitrary lineage histories. The pure expectations module is part of the pinned copied-source closure. Binding preparation, control reconciliation, native definition acquisition, manifest transport, real source truth, externally latest history and actual cloud invocation metadata remain separate behavioral checks. No binding, control or provider execution proof follows from this model.

`scopeReadView` filters owner and registration/expectation dependencies after full aggregation. This read-only closure, scoped health summaries and pagination remain outside the bounded projection model. Producer own-occurrence indexing and bound-run preparation are pure lookup steps within the mapped candidate predicate. No publication await changed.
