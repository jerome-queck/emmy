## Properties and harms

| Property | Promise and harm | Code mapping | Actual-source breaks |
| --- | --- | --- | --- |
| `ResolvedAdmission` | Unresolved or invalid policy cannot become ready. Otherwise an operation could ignore owner scope, unsupported rules, hard conflict or missing timing. | `assessPlanningPolicy` validation, applicability, exact supersession, hard constraint and timing checks; both existing caller findings | Unsupported predicate, missing timing, wrong supersession digest, foreign supersession scope, duplicate version, hard conflict, native/API bypass. |
| `ViableAdmission` | Evidenced valid scoped operations remain usable. Overbroad rules could block unrelated source/account work or let preferences replace hard policy. | `applicability`, scoped successor filtering, hard-strength selection | Source-scope bypass, global supersession, preference-as-hard. |
| `RoundedExact` | An admitted booking has the exact upward-rounded source duration. A shorter or padded block corrupts source accounting. | `assessRoundedBooking`, native `sourceTiming` consumption | Floor rounding; same real-source path also breaks `ResolvedAdmission`. |
| `ScopedSelection` | Accepted supersession retains the exact expected selected revision in the stated domain. Global replacement could erase original instructions. | Exact version/digest and applicability selection | Selected-version rewrite; scoped supersession also fails viability on its actual path. |

The graph is generated by invoking actual pure evaluation and both actual adapters on an explicit finite domain. Independent case facts define expected refusal/admission, integer-ceiling duration and exact selected revision. TLC compares those facts with production outputs. Every counterexample replays the same supplied input and actual mutated synchronous call, including full adapter output equality. Import errors, syntax errors and unrelated exceptions never count as killed mutations. Unchanged code runs again after all mutations.

Original prepared-packet retention, preflight/final-readback comparison, historical wire identity and receipt expiry are empirical/unit claims, not TLC properties. They are covered by the named tests and actual CLI driver. Their files are pinned for reviewed association only.

## Coverage, atomicity and bounds

The full source sync commit and file/function digests live in [coverage.json](../../../verification/planning-policy/coverage.json). Only advance that commit after reading the complete covered diff and replaying all intended real-source mutations. The runner checks working bytes and the bytes at that immutable commit. Verification files, this skill and the [chart](../../../verification/planning-policy/chart.mmd) are pinned separately.

`calendar-policy.mjs` remains the common source/owner semantic admission boundary. It delegates v2 rules and all native rounded arithmetic to `planning-policy.mjs`. `calendar-register.mjs` supplies native facts and consumes returned bookings. `academic-os-task-plan.mjs` supplies API evidence and retains original selections. `calendar-handoff.mjs` compares selections through existing plans and attempts. Source grouping, prerequisites, labels, protected meals, terminal intent and owner moves retain existing checks.

One evaluator or adapter invocation is one synchronous atomic graph action. Supplying the input is the preceding graph action. The graph makes no claim of a stored reducer lifecycle. Native/API I/O, acquisition, writes, durable retention and later receipt reads are separate steps outside TLC.

The domain has 87 explicit cases, 175 states and 261 edges. Fifty rounding cases cross ten actual-duration boundary values with five scheduled durations. Other partitions cover scoped unknown predicates, null/partial windows, timing evidence, three undated operation kinds, two rule revisions, exact/forked supersession, duplicate versions, hard conflict, preferences/estimates, attribution/date failures and ten actual native/API adapter cases. These are named partitions, not every combination of all inputs. Legacy arithmetic equivalence separately covers every actual minute from 1 through 1440 and nine representative or exact rounded booking values.

Assume trustworthy checker/case facts, collision-free hashes, honest supplied captures and declared source attribution. The pure entry receives adapter-normalized context; provider/parser truth is not proved. The graph covers neither arbitrary rules/durations/counts nor concurrency, async filesystem atomicity, a complete preference engine, account truth, authorization authenticity, durable at-most-once effects, gateway/module publication, deployment or installed adoption. Explicit v1 compatibility remains callable and makes no v2-policy claim.

The chart merges states with identical reader labels, hides within-label terminal stutters, and keeps all decision paths reachable. No graph exploration is removed.
