# Verify Emmy

## Launch and health

Use Node 24 or later. Run `npm ci --ignore-scripts` to install locked verification dependencies. Run `npm run agent -- help --json`. It returns `ok: true` with the metadata-defined commands. Run `npm run agent -- doctor` and `maintain --check`. Doctor checks local runtime, catalog, bindings, store references/evidence, historical records, generated drift, and restored suspension. It does not probe native tools.

Each driver command starts a fresh Node process. Run `npm run verify:behavior` for the complete mapped drive. It creates and health-checks its own synthetic temporary git repository and private home. After a surprising failure, retain the report and rerun in a new isolated session with doctor. Expected refusal controls are part of the drive.

Run `npm run check:links` to check local links and images in tracked `.md` and `.markdown` files, including hidden paths. The checker reads working-tree bytes. Targets must match the tracked inventory's exact case and exist as regular files or derived directories. Symlink targets and symlinked source paths are unsupported. Relative paths resolve from the source directory; leading slashes resolve from the repository root. Queries do not affect lookup. The checker splits queries and fragments before percent-decoding each component once.

Heading IDs follow this repository's compact GitHub-style contract. The checker takes rendered text, inline code, link labels, and image alt text from ATX and Setext headings. It lowercases Unicode, retains letters, numbers, combining marks, `_` and `-`, replaces spaces with hyphens, and removes other characters and whitespace. It allocates duplicate suffixes in document order against all prior IDs. Fragments match exactly after decoding. These rules do not promise universal GitHub renderer parity.

Diagnostics name the source, parsed destination, and containing block's start line and range. CommonMark supplies block positions rather than exact inline-link lines. The checker handles inline and resolved reference links while ignoring code examples and external URI schemes. Raw HTML links and custom HTML anchors are outside its scope. Non-Markdown fragments receive only file-existence validation; directory fragments are unsupported. `node --test test/markdown-links.test.mjs` drives the delivered CLI in temporary Git repositories, including deliberate missing-file and bad-anchor failures. The checker exits 0 for success, 1 for link findings, and 2 for argument or source-inventory errors. `--root <directory>` selects another repository root for fixtures.

Run `npm run check` for Markdown links and their CLI fixtures, generated references, full behavior, existing merge tests, bounded responsibility and calendar properties/mutants, the unchanged merge-policy verifier, and the [publication model](../publication-contract/SKILL.md). The model requires Java 21 and a hash-pinned TLC jar. Apply the installed pstack maintenance workflows after feature changes. Generated indexes do not perform independent source review or advance formal pins.

Cloud restart evidence uses Linux boot/PID namespace/time namespace/start-tick witnesses, never PID inequality alone. `npm run check` runs parser, owner and legacy-file unit controls; supported Linux drives actual same/fresh processes and interrupted owner fixtures. macOS records unsupported evidence explicitly and refuses acceptance resume/recovery without claiming a cloud failure. Ordinary pure work still runs. The legacy migration driver uses labelled synthetic analogues and preserves their original hashes; it cannot substitute for the parent executor's actual retained files.

Use `node scripts/verify-behavior.mjs --focus fleet` and `node --test test/fleet.test.mjs test/fleet-history.test.mjs test/fleet-semantics.test.mjs` for [fleet health and sign-in recovery](features/fleet.md).
