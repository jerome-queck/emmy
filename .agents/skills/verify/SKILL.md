# Verify Emmy

## Launch and health

Use Node 24 or later. Run `npm ci --ignore-scripts` to install locked verification dependencies. Run `npm run agent -- help --json`. It returns `ok: true` with the metadata-defined commands. Run `npm run agent -- doctor` and `maintain --check`. Doctor checks local runtime, catalog, bindings, store references/evidence, historical records, generated drift, and restored suspension. It does not probe native tools.

Each driver command starts a fresh Node process. Run `npm run verify:behavior` for the complete mapped drive. It creates and health-checks its own synthetic temporary git repository and private home. After a surprising failure, retain the report and rerun in a new isolated session with doctor. Expected refusal controls are part of the drive.

## Evidence and teardown

Full and failed runs retain `.local/verification/behavior-*/report.json` plus immutable synthetic records/evidence. The report survives temporary-repository cleanup. Check that named path exists. Failed command and assertion output remains available even when the driver exits nonzero.

Dispatch runs retain their complete synthetic private home under the report's `retainedDispatch` directory, including bindings, source evidence and immutable records. The original failed controls remain evidence. Actual installed bootstrap recovery and native readbacks require the separate [acceptance](../../../docs/dot-verification.md#verify-persistent-native-dispatch-recovery).

Briefing runs also retain the complete `briefing/` tree and `retainedCheckedBody`. The driver rereads that body after deleting its temporary repository. Interrupted pending snapshots and corrupt controls remain evidence. A simulated canonical response proves the local boundary, not public-main publication. Run a separate real public acquisition after the generated bundle is published.

The full drive includes ten record/archive/restore/import checkpoint cancellations and one briefing-cache cancellation. A child stops at each named boundary, then the driver sends SIGKILL and replays. This is evidence at those boundaries. It is not all-instruction crash durability or filesystem flush proof.

Checkpoint reads wait for the writer's complete newline-terminated frame. An empty/partial/full marker control proves that file existence alone cannot trigger parsing or cancellation. The last observed incomplete frame, bounded to 4096 characters, complete marker bytes and child output remain in the report when a checkpoint assertion fails.

Each executable criterion reacquires canonical repository identity and reevaluates restored eligibility from the pinned epoch and observations at the current clock. A first check changing tracked dependency bytes or hiding git identity fails; the next check remains unexecuted with unknown evidence. An unchanged two-check control executes both. Restored authority expiring during a three-second check blocks the next command; current authority permits both. Post-execution inspection remains required. These observations do not establish atomic filesystem pinning or atomic revocation.

Local-check output limit, normal leader exit, timeout, and handled SIGTERM/SIGINT each send one owned POSIX group request. The driver logs actual requests and proves descendants disappear before harness teardown. Normal exit waits for a complete readiness marker from a live descendant that inherits the output pipes. A repeat-only EPERM control delegates the first request to the OS and denies only a redundant request. The output-limit result retains one signalled attempt and no cleanup errors. Injected first and persistent EPERM controls retain failed evidence, process-group identity, and explicit unverified cleanup. Their later harness group cleanup proves only teardown of those fixtures, not product cleanup under denied signals. Detached descendants and hostile-code containment remain outside the contract. The driver cleans only its own temporary state and processes, then retains evidence under this checkout's ignored home.

## Scope

Observed local bytes and bounded Node output prove their declared checks. Imports remain reported. The synthetic E002 analogue uses its own failing/corrected repositories and actual CLI negative controls; it consumes no personal root evidence. Required independence stays `external-review-needed` even after local success and an imported different reviewer name.

No result establishes native dispatch, Dot installation, account access, schedules, delivery, merges, deployment, or hardware-loss recovery. Keep those [native probes](../../../docs/dot-verification.md) separate.

Briefing's advisory policy is behaviorally covered. Its reviewed-source hashes do not add formal semantics or prove source truth, actual correction recovery, automatic invocation or native output identity.

Run `npm run check:links` to check local links and images in tracked `.md` and `.markdown` files, including hidden paths. The checker reads working-tree bytes. Targets must match the tracked inventory's exact case and exist as regular files or derived directories. Symlink targets and symlinked source paths are unsupported. Relative paths resolve from the source directory; leading slashes resolve from the repository root. Queries do not affect lookup. The checker splits queries and fragments before percent-decoding each component once.

Heading IDs follow this repository's compact GitHub-style contract. The checker takes rendered text, inline code, link labels, and image alt text from ATX and Setext headings. It lowercases Unicode, retains letters, numbers, combining marks, `_` and `-`, replaces spaces with hyphens, and removes other characters and whitespace. It allocates duplicate suffixes in document order against all prior IDs. Fragments match exactly after decoding. These rules do not promise universal GitHub renderer parity.

Diagnostics name the source, parsed destination, and containing block's start line and range. CommonMark supplies block positions rather than exact inline-link lines. The checker handles inline and resolved reference links while ignoring code examples and external URI schemes. Raw HTML links and custom HTML anchors are outside its scope. Non-Markdown fragments receive only file-existence validation; directory fragments are unsupported. `node --test test/markdown-links.test.mjs` drives the delivered CLI in temporary Git repositories, including deliberate missing-file and bad-anchor failures. The checker exits 0 for success, 1 for link findings, and 2 for argument or source-inventory errors. `--root <directory>` selects another repository root for fixtures.

Run `npm run check` for Markdown links and their CLI fixtures, generated references, full behavior, existing merge tests, bounded responsibility and calendar properties/mutants, the unchanged merge-policy verifier, and the [publication model](../publication-contract/SKILL.md). The model requires Java 21 and a hash-pinned TLC jar. Apply the installed pstack maintenance workflows after feature changes. Generated indexes do not perform independent source review or advance formal pins.

Cloud restart evidence uses Linux boot/PID namespace/time namespace/start-tick witnesses, never PID inequality alone. `npm run check` runs parser, owner and legacy-file unit controls; supported Linux drives actual same/fresh processes and interrupted owner fixtures. macOS records unsupported evidence explicitly and refuses acceptance resume/recovery without claiming a cloud failure. Ordinary pure work still runs. The legacy migration driver uses labelled synthetic analogues and preserves their original hashes; it cannot substitute for the parent executor's actual retained files.

Use `node scripts/verify-behavior.mjs --focus fleet` and `node --test test/fleet.test.mjs test/fleet-history.test.mjs` for [fleet health and sign-in recovery](features/fleet.md). Canonical journal snapshots retain captures, parent read tickets, scoped dispositions and separate pending/send/readback states. Receipts remain reported. No fixture performs authentication, parent app reads or actual Dot delivery.
