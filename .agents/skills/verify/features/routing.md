# Responsibilities and proposals

## User route

Fill private bindings and a definition from [onboarding](../../../../docs/onboarding.md). Run `responsibility --file <definition>`, then `reconcile --id <id> --as-of <UTC>`. Adoption returns criterion `specHash` values for ready-to-use imports. The retained goal/context survives fresh processes.

Active definitions require finish criteria. Exact subject includes project, intended canonical repository, executor, designated host/native project, path, full revision, and dirty digest. Omitted executor defaults to local Codex. Supplied work class and cloud rationale are validated. Nonlocal coding requires a reason and explicit scoped cloud authority. Codex Cloud also requires a prepared environment.

Definitions name parent hashes. Concurrent heads block proposals until one definition references every head. Native pending or uncertain effects yield rediscovery only across time and revision changes. A native task without an `effectKey` also requires rediscovery and exposes its native ID as uncorrelated. Its completion cannot prove that the current intended effect completed. Effect keys bind responsibility, stable target identity, intended effect, and occurrence. They do not enforce native at-most-once execution.

Selectors are `key:`, `id:`, `name:`, `path:`, or `repository:`. Ambiguous names require an explicit choice. Resolution preserves native identity when source evidence is unavailable. It cannot substitute this repository or projectless work. Non-Git roots and roots lacking a canonical origin need source evidence before a coding definition.

ChatGPT conversational Projects return an unsupported native coding membership result. Cloud Work is separate.

## Coordinator model policy

The private objective's `dispatch.coordinatorRequestedSettings` is separate from child `requestedSettings`. Its scope names the same objective and coordinator role. Omission requests exact Sol Medium. An explicit request selects exact Sol High for heavy reasoning. Above High or a different coding model requires `oneTimePermission` binding the owner source to the exact objective, role, model and effort. A generic override reference is insufficient. Historical records remain readable; mismatched settings require rediscovery. Explicit requests match actual recorded settings exactly. Descendant policy revisions retain immutable dispatcher identity, authority and effect correlation. Pending or uncertain attempts still require rediscovery. `native-dispatch` drives scoped Medium, wrong scope, missing source, descendant correction, unchanged authority and exact readback evidence. The finite domain adds Low, Luna Max, role separation, refusal of unrequested stronger effort, freshness and preserved launch uncertainty, with five paired production mutants. These fixtures authenticate neither owner source nor provider execution.

The native-dispatch driver also covers generic escalation refusal, wrong objective/role/model/effort permissions, and an exact one-time permission for both child and coordinator. Five paired production mutations prove the exceptional-choice gate and each scope comparison can fail. These checks do not authenticate permission sources.

Standard/non-fast is the default for coding sessions, coordinators and helpers. Fast or Ultrafast requires explicit owner approval for that exact task, role and tier. An unanswered request is not approval; continue Standard without waiting. Never inherit an accelerated tier from a parent, saved session or broader preference. Model/effort permission does not grant speed permission. Use supported native/config controls only, verify recorded settings separately, and report an unavailable tier control or readback.
