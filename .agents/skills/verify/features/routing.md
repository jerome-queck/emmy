# Responsibilities and proposals

## User route

Fill private bindings and a definition from [onboarding](../../../../docs/onboarding.md). Run `responsibility --file <definition>`, then `reconcile --id <id> --as-of <UTC>`. Adoption returns criterion `specHash` values for ready-to-use imports. The retained goal/context survives fresh processes.

Active definitions require finish criteria. Exact subject includes project, intended canonical repository, executor, designated host/native project, path, full revision, and dirty digest. Omitted executor defaults to local Codex. Supplied work class and cloud rationale are validated. Nonlocal coding requires a reason and explicit scoped cloud authority. Codex Cloud also requires a prepared environment.

Definitions name parent hashes. Concurrent heads block proposals until one definition references every head. Native pending or uncertain effects yield rediscovery only across time and revision changes. A native task without an `effectKey` also requires rediscovery and exposes its native ID as uncorrelated. Its completion cannot prove that the current intended effect completed. Effect keys bind responsibility, stable target identity, intended effect, and occurrence. They do not enforce native at-most-once execution.

## Source and drive

`responsibilities.mjs` adopts and reconciles. `work.mjs` owns exact routing, authority, heads, and effect identity. `dispatch.mjs` reads validated private selection/definitions/task evidence and projects native advice. Scenarios `persistent-context`, `binding-boundaries`, `native-effect-correlation`, `native-dispatch`, `definition-concurrency`, and `probe-packet` exercise restart/replay, inherited keys, invalid rationale/work class, repository mismatch, cloud scope, unkeyed task completion across intended-effect edits, concurrent observations, explicit fork resolution, and actual onboarding packet bytes.

`probe --nonce <fresh-value>` retains all eight proposed native capability prompts. It does not install instructions or run them.

## Boundaries

Bindings remain local input, not authenticated native permission. A repository mismatch prevents local-check execution and work. Current native discovery remains required before actual execution. Partial inventory cannot prove absence. New concurrent input requires another pinned review.

## Standing policy and native planning

Same-objective continuation requires its prior context. Rediscover uncertain dispatches before retrying. Compare requested models with resolved project settings and actual execution separately. Scoped explicit human settings prevail. Do not modify global settings.

Current success does not establish creation-time state or erase a contrary owner report. Missing, conflicting or omitted membership stays unverified and requires rediscovery before retry. The CLI validates reported metadata; native truth and execution remain external.

## Private dispatcher recovery

Follow [the private schema and procedure](../../../../docs/native-dispatch.md). `dispatch --project <project-key> --as-of <UTC>` recovers the selected dispatcher and known objectives. `--id` reads one objective, while `--context-needed` permits same-objective continuation advice only within retained authority. A new objective uses a new definition and fresh native child. Exact private bindings stay in the existing archived home.

`native-dispatch` drives source-digest checks, exact supported create fields, attempt/pending/uncertain recovery, explicit no-effect resolution, ready child/cursor recovery, membership and recorded-setting refusals, standing scope reuse, distinct-objective child reuse refusal, unchanged journal reads and suspended restore. The finite `dispatch-recovery` property adds a bounded production-function domain and paired source mutations. Neither verifies provider execution, inherited effective access, actual native creation or an automatic hook. Keep setup invocation, installed guidance, and later ordinary-human adoption separate.
