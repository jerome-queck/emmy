# Reconciliation and correction

## User route

Run `reconcile --id <id> --import <bundle> --as-of <UTC>`, or omit `--id` to review all responsibilities. Imports are optional. Actual local inspection supplies current git identity and artifact bytes. Review output includes context, effective cutoff, observation refusals, criterion support/assurance, open findings, exact repairs, corrections/regressions, and proposals.

Every live review includes actual completion time, including cloud, unbound, or conflicting targets that produce no local observations. The requested `asOf` remains in `requestedAsOf`; fixed historical replay uses its pinned time. Imported future, stale, partial, unavailable, or foreign records remain diagnostics. New eligible coverage does not erase a retained failure. Rechecks must follow the latest failure, name the exact finding/original failure, bind the current expected subject, and satisfy every original affected criterion. Weaker criteria cannot close old failures. Two repeated actual failed repairs propose diagnosis even after native completion. That continuation requires fresh native rediscovery; pending/uncertain effects keep rediscovery-only priority, and expired scope yields observation/decision. Exact closure suppresses duplicate completed green work.

A local-check pins a repository-relative Node script, digest, arguments, expected exit, finite timeout, and separate `run-local-check` authority. Its source/output/exit/runtime are retained. Reported imports cannot acquire local assurance. Required independent review remains externally blocked.

Before each executable criterion, the canonical inspector reacquires repository path, repository identity, revision and dirty bytes. A mismatch or unreadable identity yields unknown evidence without executing that command. Restored eligibility uses the pinned epoch and observations with a fresh live cutoff for each command. Earlier source-changing failure remains retained. Post-execution inspection still detects changes during execution. These checks do not atomically pin filesystem bytes or revoke running commands.

Each child records at most one cleanup attempt across output, timeout, cancellation, exit, and close callbacks. Successful signalling waits for close, including normal leader exit with inherited descendants. An owned process-group signal denied with `EPERM` produces failed evidence with `process-group-cleanup-failed`, its process-group ID, and `cleanup.status = unverified`. The operation stops waiting without claiming termination. Cancellation reports the same uncertainty as an operational error. An unverified group may still contain processes; the driver records its later fixture cleanup separately. The original observed EPERM cause remains unresolved.

## Source and drive

`briefing --home <private-home>` returns current or cached readable guidance, or an explicit unavailable state. With `--file <draft.json>`, it validates declared sources and renders advisory Markdown. Digest/reference mismatches return `revise` without a normal body. Cached/unavailable guidance or unavailable correction recovery returns `degraded` with useful qualified output. Invalid input exits 2. The existing native note/register owns durable corrections.

`src/briefing.mjs` owns acquisition, cache, parsing, one assessment and exact rendering. Scenarios `briefing-guidance`, `briefing-draft` and `briefing-boundaries` drive a real child CLI with harness-owned canonical transport. They verify source pins and bytes, one total stage-local retry within the shared deadline, successful-recovery diagnostics, retry refusals, exact returned/retained body digest, scoped suppression and conflict, separate capability scopes, historical budgets, coverage/age limits, incompatible versions, interruption and corrupt fallback. Main cannot be repinned after acceptance. Unknown causes, permanent responses and data failures cannot retry. Journal record/evidence bytes stay unchanged. The fixture supplies no native fact and product configuration supplies no endpoint override.

The same assessment produces private policy evidence and the human body. The driver binds its exact input/guidance/time/body, verifies returned and retained Markdown bytes match, and parses the body with CommonMark. It checks exact HTTP(S) link destinations with Unicode, delimiter and literal entity controls, plus literal entity text in scopes, coverage and gaps. Private assessment URLs stay canonical. The driver withholds opaque and unsafe references, excludes unchecked labels and routine prose, and refuses credential-bearing URLs before fetch or draft retention. Duplicate decoded field names anywhere in a draft, including escaped aliases and objects inside arrays, are also refused before fetch or retention. Valid formatting and original draft bytes remain intact. Conflict source IDs and opaque readbacks remain available in private assessment evidence. Missing web links remain a useful human limit.

`responsibilities.mjs` performs live inspection and pure reconciliation; `work.mjs` decides evidence/repair/trigger policy; `records.mjs` parses and retains inputs. Scenarios `self-check-repair`, `evidence-boundaries`, `live-cutoff`, `local-check`, `local-check-cleanup`, and `trigger-evolution` cover actual corruption, later recurrence, unreadable-after-green, two-criterion exact closure, false-claim correction, wrong identities/ages/coverage, backdated cloud reviews, bounded child cleanup, first and persistent injected EPERM, E002 analogue, missed/no-op/delivery gaps, retirement conflicts, native uncertainty, and merged obligations.

The local-check drive also changes a tracked imported dependency, hides git identity, and proves the second command stays unexecuted. Its unchanged two-command control executes both.

The cleanup drive counts actual group requests for output limit, normal leader exit, timeout, and handled SIGTERM/SIGINT. Its repeat-only EPERM control calls the OS on the first request and denies only a redundant request. Positive controls prove descendant disappearance before harness teardown. The normal-exit descendant supplies a complete readiness marker and inherits the leader's output pipes. Bounded helper predicates classify independent calls and do not prove this asynchronous lifecycle.

## Boundaries

An earlier passing repair stays in its immutable review when later deterioration makes that attempt currently insufficient. A native run, useful outcome, and delivered notification require separate evidence. Only a known explicit due window is evaluated; later windows need native discovery. Retired methods stop their local-check execution, preserve failures, and expose pending native disablement. Imported enabled/disabled contradictions need explicit scope-safe supersession.

Briefing consistency is advisory. Its reviewed source manifest does not prove new formal policy. Downloaded guidance executes no code and grants no authority. Output receipts never replace correction storage. Native invocation, later-turn recovery and exact displayed output remain unverified until their actual probes pass.

The approved two-document briefing bundle includes standing thread/model rules and the complete persistent calendar procedure in the operating brief. `maintain --write` regenerates that data. The real briefing drive verifies transport and exact delivered bytes, not semantic compliance with this prose. After publication and installation, perform a real canonical guidance refresh and inspect the returned text and digest. Native Calendar creation, duration, duplicate prevention, and later-turn adoption require the dedicated native acceptance contract.

Native calendar acceptance separately covers Task/Event identity, duration, move, inventory coverage and timezone consistency. A resize cannot prove a move. Free/busy can omit Tasks and transparent Events. Conflicting Calendar/embedded-Task clocks stay unresolved until attributable time/zone evidence or an explicit decision resolves them. The delivered procedure requires those distinctions; the fixture driver does not prove native enforcement. Later unrelated human-turn acceptance requires its own guidance, fresh-thread membership and actual model readbacks, without a setup reminder.
