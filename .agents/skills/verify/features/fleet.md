# Fleet health and sign-in recovery

Run `node scripts/verify-behavior.mjs --focus fleet` and `node --test test/fleet.test.mjs`. Read [the contract](../../../../docs/fleet-health.md) and [sign-in skill](../../sign-in/SKILL.md) first. The focused driver uses a separate synthetic private home, actual CLI processes and byte-retained receipts. It performs no native read, sign-in, send, or schedule change.

Drive source age separately from acquisition age. Expired login, denied action, unavailable tool, timeout, pressure, monitoring failure, workflow failure, suspended, unknown, pending and recovered remain distinct. A disabled or missed expected run is visible. Completed execution needs outcome evidence; required delivery needs its own reference. Failed monitor coverage makes dependent health unknown. Do not call partial coverage healthy.

Repeat equal failures and results. Retain one job and one unchanged alert episode. Dismiss exactly one episode and retain a scoped correction. Reacquire current evidence for recovery, then introduce a recurrence and verify a new episode. An uncertain notification cannot be resent. A separate synthetic parent readback is needed for reported acknowledgment.

Submit bounded parent reads, verify reservations/backpressure, retain admission before its ticket, and preserve uncertainty after a lost response. Reconcile exact ticket, checkpoint, source scope and bytes before completion. Inspect resource-pressure deferral, terminal deduplication, replay, archive and restored suspension. Repeated commands return no fresh execution ticket. The durable per-head intent finishes only the same pure journal publication after interruption. It never executes the parent read.

The driver retains its synthetic homes under `report.retainedFleet` and the sibling `fleet-staleness/` directory. Reopen canonical record/evidence bytes after temporary-repository cleanup. Additional unit controls exercise the sign-in branches, secure form preference, matching OTP issuer, one scoped retry, persistent denial, exact protected account, strict JSON and secret-field refusal.

`fleet-state.mjs` owns the pure projection and reducer. `fleet-schema.mjs`, `bounded-json.mjs`, and `fleet.mjs` own parsing, real byte retention and serialized publication. `records.mjs` replays every retained state transition and validates definition/root/parent/epoch and receipt edges. Responsibility reviews pin fleet inputs and replay them; doctor exposes stale/unknown fleet and unfinished publication intents. `signin.mjs` accepts only nonsecret advisory metadata.

The bounded `fleet-contract` property has 77 production predicates and eighteen paired actual-source mutants. Read [the coordination mapping](../../coordination-contract/SKILL.md). These checks assume attributable but unauthenticated reported sources and a cooperative parent obeying each ticket. They do not acquire native state, enforce provider limits, authenticate authority, prove external exactly-once actions, send messages, establish actual sign-in, or prove later adoption. Actual parent I/O, installed bytes, guidance loading, Dot send/readback, and ordinary-turn use remain separate gates.
