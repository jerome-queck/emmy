# Restoration suspension

Run `node verification/restoration-suspension/check.mjs` with Node 24+, Java 21, and the existing pinned `.local/tools/tla2tools-1.7.4.jar`. Results and copied-source mutations are retained under `.local/verification/restoration-suspension/`. No product files are mutated. The command checks the mapped static production import closure, including `src/content.mjs`, against the source commit in [coverage.json](../../../verification/restoration-suspension/coverage.json). `--development` bypasses this source gate and cannot support acceptance.

Read each result with the installed `pstack:statechart` skill. Inspect the counterexample and its `replay.json`: a syntax error, source pin refusal, unrelated exception, or missing actual copied-function replay is not a property counterexample. The command checks baseline, real-source guards broken in isolated copies, and restored baseline.

A restored home must remain suspended until all four categories have eligible evidence in that epoch. Unavailable supersession and stale observations revoke readiness. The ordinary reconciliation path must not emit work proposals while the restore gate is suspended. Wrong target provenance, authority scope, coverage, and subject must not support the fixture's readiness. Node built-ins and checker code are trusted; dynamic imports and external package behavior are outside the source guard. The model uses actual `restoredState`, `currentObservations`, `observationStatus`, `authorityStatus`, and `reconcileState`; its graph records external arrivals separately from reconciliation. Each reconciliation is one synchronous production call. Archive and epoch publication are external boundaries, not an atomic modeled restore. Existing publication verification owns its own interleavings.

The finite domain has two sequential epochs, one local subject, four required categories, one admitted observation per category per epoch, at most one defective category, one unavailable tasks successor and one recovery, a three-record supersession chain, and one expiry clock change. Evidence is parsed through actual record parsers, with synthetic local-inspection provenance injected for the target. The second epoch follows a complete first epoch. The time domain is four timestamps; freshness is 10 seconds. The graph checks every ordering admitted by these bounds; no fairness or liveness claim follows. Import ordering, actual inspection, storage, backup and restore I/O, authentication, concurrent writes, native execution and delivery are excluded. Dispatch's separately declared `nativeRemote` mode permits reported target evidence with references and is outside this graph.

Before advancing the source sync commit, read every covered source and dependency diff, including moved callers, publication and fixed-plan owners; confirm the graph still maps to actual atomic boundaries. Run the installed `pstack:maintain-formal-verification-skill` and empirical verification workflow. Preserve product failures and replay counterexamples against actual functions. Do not weaken properties to make them pass. Independent source review and acceptance remain separate gates.
