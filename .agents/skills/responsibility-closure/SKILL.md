# Responsibility closure

A retained failed criterion must remain visible until a correctly linked repair has a later eligible passing recheck of that finding's original criterion. Otherwise a later pass or weaker definition can hide unfinished work.

From the repository root run `node verification/responsibility-closure/check.mjs` with Node 24+, Java 21, and the repository's hash-pinned TLC jar at `.local/tools/tla2tools-1.7.4.jar`. The command makes a private evidence directory under `.local/verification/responsibility-closure/`, prints its location and runs baseline, three copied-source mutants, and restored baseline. A failed baseline is a finding or a model error, not a pass. A mutation counts only when TLC reports `Closure` and the corresponding actual-code replay reproduces it. Read the output and `graph.json`, `tlc.out`, and `replay.json`; syntax, tool and assertion failures are not counterexamples. Read TLC results with the installed `pstack:statechart` skill by name.

The source mapping was reviewed at `693b277f8dc0e1a0acc03a5e739bf057c403479e`: `src/responsibilities.mjs` `reconcileState` retains review findings and invokes `repairStatus`; `src/work.mjs` `repairStatus`, `observationStatus`, `sameSubject`, and `criterionHash` check links, freshness, subject and original criterion. `src/records.mjs` supplies fixture parsing and record identity. `verification/responsibility-closure/graph.mjs` generates the actual-source graph and `check.mjs` checks its independent closure condition. The private evidence contains the generated TLA+ graph.

The finite domain has one responsibility, two definitions, one retained failure of one criterion, one passing recheck, one completed native-effect observation, one incorrect no-recheck repair, one incorrect failure-link repair, and one valid repair. Record arrivals are each at most once; repeated reconciliation is allowed. A fixed failure review is computed by a synchronous call then separately admitted as a retained record. Another synchronous reconciliation consumes the selected records. Inputs use fixed timestamps, one current local subject and non-conflicting observations. One original criterion is in the actual finding; this does not prove multi-criterion findings. Publication, asynchronous reads and saves, native state, authentication, arbitrary timestamps or inputs, crashes, restoration, recurrence and effects are outside this graph. Retention of the first review and arrival of each record are environment assumptions, not proven I/O.

On a covered change, run the old check, inspect the complete covered source diff from the sync commit, including moved owners and call atomicity, then update the model and mapping. Never move the sync commit without that review. Replay real source counterexamples and distinguish broken source from a modeling error. Do not weaken the promise to hide a product finding. Use `pstack:maintain-formal-verification-skill` when refreshing the verification. Integration and independent review are separate gates.
