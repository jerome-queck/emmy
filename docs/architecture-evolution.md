Each connected machine and the cloud computer remains a distinct execution environment; access and installation need separate readbacks.

This reassessment compares callable owners with the [shared planning objective](academic-os-alignment.md), [API task-plan contract](academic-os-task-plan.md), operating brief and responsibility architecture. A first local assurance slice does not complete whole-repository migration.

## Shared planning policy first slice

Native register assessment and the Academic OS adapter already call `assessCalendarPolicy`. Its schema-version-one supplement owns assignments, occurrences, ordered groups, exact bindings, scoped owner field protections and terminal intent. It is narrower than the documented general rule bundle.

The bounded [shared planning policy](planning-policy.md) now resolves immutable rule IDs/revisions, attributable sources, effective windows, operation/account/source scope and exact supersession. Both existing callers consume the rounded-booking predicate. Applicable unsupported predicates, unresolved scope/timing and conflicting hard definitions refuse dependent application. Preferences and estimates cannot override hard constraints. Exact selected versions and a separate computed policy digest remain in prepared packets and readback.

Native rounded validation now lives in the shared evaluator, with exhaustive historical arithmetic equivalence and refusal controls. Version-two API operations without timing require exact evidenced nonapplicability or unresolved timing. Historical version-one semantics remain explicitly selectable and make no new-policy claim. Preserve coherent source groups, prerequisites, concise source titles, absent descriptions, protected meals, completion, dismissals, exclusions and owner-moved work. Campaign preferences remain scoped. Invent no filler or universal weekly rule.

## Exact-ID gateway and module convergence remain separate work

Academic OS owns the proposed mutation gateway and provider-to-module publication. Reuse its existing annotation-preserving ID mapping and recovery store where verified. Emmy supplies versioned intent, policy associations and exact operations through that supported boundary.

A gateway slice needs fresh provider preflight, per-Task serialization, a narrow changed-field patch, original uncertain-result retention, same-ID reconciliation before retry and a verified saved receipt. Creates need stable source-occurrence and operation identities. Titles never substitute for native IDs. Completion, owner dismissal, cancellation and supersession remain distinct.

Publish the affected module after verified application. Expose pending mirror publication separately from provider failure. Direct UI changes require complete polling coverage and token-expiry rebuilds. Preserve the last good generation after invalid YAML or offline Drive, report the affected module stale and retain source annotations. Generation, provider acquisition time, module publication time and content hash distinguish remote freshness from delayed Drive propagation. Installed cadence, service, credential and bridge changes require separately authorized delivery/readback.

Earlier contracts fix planning to Dot-cloud and local execution to a cloud-approved handoff. Studio-primary intent does not silently rewrite those wire contracts. A later identity migration must name planner/coordinator/executor separately, update every caller and test stale plans, completion-versus-reschedule races and cross-environment refusal. Preserve policy/gateway/module requirements through that migration.

## Verifiable migration order

1. Establish local assurance through the existing aggregate ingress. Preserve prior checks and obtain fresh independent review before integration.
2. Extend the integrated bounded shared policy slice only from evidenced new predicates. Native/API callers already consume the first predicate together. Preserve historical semantics explicitly. Add empirical journeys and an area-named formal skill with real-source mutants.
3. Coordinate a separately owned Academic OS gateway slice. Verify exact counterpart compatibility, then separately accept provider application and uncertain-result reconciliation.
4. Complete provider-to-module and direct-UI convergence in Academic OS. Drive offline, pagination, invalid-YAML and generation-drift controls before separately changing installed refresh cadence.
5. Migrate coordinator/executor identities and ordinary task ingress to Studio-primary intent. Verify each machine independently; retain exact saved project/host/settings and launch uncertainty.
6. Revisit fleet, morning, dispatch, cloud and persistence one subsystem at a time. Remove duplicate owners only after callers migrate. Split formal contracts by subsystem while preserving empirical coverage and replay.
7. Rebuild portable consumers and perform separately authorized installation and ordinary-use acceptance. Source integration alone proves none of those outcomes.

Every unit needs callable ingress, refusal controls, code/property mapping, explicit atomicity/bounds/assumptions and its required independent review. Read TLC results with `/statechart`. Missing coverage remains unfinished. A bounded graph is not a whole-system proof.
