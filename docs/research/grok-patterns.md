# Grok Bot patterns for Emmy

Access date for every linked source is **2026-10-22**. Scope is the xAI Grok Bot desktop product. No installed-app data, UI, account, Bot, routine, or template was inspected or changed by this worker.

Evidence labels mean the following.

- **DOCUMENTED** means an opened official product document states the behavior. It is not a live account test.
- **PUBLIC CONFIG** means an opened creator template/profile states its intended behavior. It is not proof that the Bot executes it reliably.
- **ORIGINAL CODE** means an opened author-owned repository file contains the described structure.
- **RECOMMENDATION** means an Emmy design judgment. It is not a claim about Dot capabilities.
- **UNVERIFIED** means the sources or live test did not establish the claim.

Throughput checkpoint is n/a, read-only investigation. The pstack how exploration ran as one bounded research slice. Unslop and technical-writing shaped the report. No child agents ran.

## Main finding

**DOCUMENTED.** Grok Bot's official internal-use pattern has one chief of staff coordinate specialists. Bots message asynchronously and share project context. Its official CoS starter produces a digest tied to priorities, with a source, significance, next action, and required decision. [Introducing Grok Bot](https://x.ai/news/introducing-grok-bot), [official use cases](https://docs.x.ai/grok-bot/use-cases).

**RECOMMENDATION.** Port the coordination pattern to Emmy. Keep one user-facing chief of staff, named outcomes, local coding executors, linked evidence, and small reusable procedures. Give Emmy broad responsibility to notice, investigate, prepare, route authorized work, check results, and follow through. Add specialists when an actual recurring responsibility earns one.

**UNVERIFIED.** No public adoption ranking or install counts were established. The sample includes official Marketplace featured profiles and relevant public engineering configurations. Call them featured or publicly shared, not the most popular or proven. The official Marketplace identifies dr eggbot and Projects Manager as featured. [Marketplace](https://x.ai/bot/marketplace).

## Two architecture options

Both options below are RECOMMENDATIONS. Neither was implemented or tested by this research worker.

| Choice | Operation | Tradeoff | Initial proof |
| --- | --- | --- | --- |
| **A. Emmy coordinates native Codex chats. Recommended first.** | Emmy reads the live project/chat inventory, reconciles it with a small project registry, and hands authorized goals to named local Codex chats. Store role, host, repo, task identity, next action, and evidence pointers. Native scheduled checks refresh only watched work. Cloud computer handles research and app work. Codex cloud requires an explicit reason. | Fewest new moving parts. Depends on the actual Dot-to-Codex bridge. Cross-chat reach, creation, continuation, notifications, and host targeting need capability probes. A registry must not become a competing task system. | One real harmless local job. Verify destination host and repo, visible task, continuation, produced artifact, independent check, and final receipt. Repeat after restart and with the target host unavailable. |
| **B. Emmy submits durable work to local runners. Later scale option.** | Emmy submits a typed job to a small authenticated queue. A runner on each authorized Mac claims jobs for that host and invokes the configured coding harness. A job ID, attempt, lease, request hash, artifact revision, and event log support recovery. Emmy reads results and makes the next coordination decision. | Survives intermittent links and supports multiple Macs without serial SSH delegation. Adds runner lifecycle, authorization, secret handling, upgrades, and cancellation work. Requires a supported authenticated transport from Emmy. | Re-deliver a request and prove one effect. Kill a runner, recover its lease, and resume safely. Prove host mismatch, stale evidence, canceled jobs, and uncertain external writes cannot pass as success. |

## Responsibilities, schedules, and recovery to carry forward

**RECOMMENDATION.** Give Emmy ownership of orientation and follow-through. It can inspect authorized work, identify stalled outcomes, gather missing context, prepare reviewable plans, route approved goals, monitor current jobs, run reversible verification, consolidate useful findings, open artifacts, and propose repo or skill improvements. A narrow immutable list of allowed task types would age poorly. Use clear source, action, host, and outcome boundaries.

**RECOMMENDATION.** Begin with one concise daily priorities brief and named-job watches. Prefer event updates when the platform supports them. Quiet checks should report a meaningful change, completed outcome, failure, or needed decision. A periodic routine-health check should detect missed runs and stale inputs. A separate friction review can propose verification or documentation changes with evidence. Do not wake every project or specialist on every tick.

**RECOMMENDATION.** Store durable work records outside chat memory. Include job ID, source request, authority, owner, host, repo, current revision, state, next action, last observed time, and evidence. Use queued, running, awaiting input, verifying, complete, failed, canceled, and uncertain states. Keep the last known source timestamp visible when an input is unavailable.

**RECOMMENDATION.** Recover by re-observing the real task and artifact before retrying. Retry reads and demonstrably idempotent work. Check whether an external write occurred before repeating it. An offline designated host stays offline work, rather than silently moving to another Mac or cloud. Resume after authentication from the checkpoint. A notification or agent self-report cannot close the job without the required artifact evidence.

**RECOMMENDATION.** Good formal properties for the parent implementation are one active claim per job, no unauthorized dispatch, no machine substitution, no complete state from stale evidence, no merge after the verified revision changes, no future retries after cancellation, and duplicate delivery converging on the same result. Model checks should complement real route and recovery journeys.
