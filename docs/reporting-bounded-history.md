# Bounded history exporter

The experimental batch-v2 exporter preserves one registered owner, one anchor and the original full source scope. Existing batch-v1 APIs and remote inventory-v2 and anchor-v1 schemas remain available. Production adoption is blocked pending accounting review, exact-shape capacity evidence, independent review and native runtime acceptance.

`src/automation-reporting-bounded.mjs` exposes `beginBoundedHistory`, `advanceBoundedHistory`, `advanceBoundedPublication`, `respondBoundedPublication`, `recoverBoundedPublication` and `retryBoundedPublicationRead`. The [behavioral mapping](../verification/automation-reporting/bounded-coverage.md) describes the executable controls and remaining gaps.

Each request names an ordinary absolute `stateDirectory`, a stable admitted `jobId`, and a distinct callback `executionId`. A continuation supplies the exact returned `jobLedger`. Capture continuation also supplies the returned `captureId` and `cursor`. A changed request does not renew a claimed execution. A separate execution marker prevents reuse of an execution ID under a newer ledger cursor. The exclusive claim reserves remaining allowance before source work. An unfinished claim leaves allowance unavailable and leaves any provider effect uncertain.

The [accounting revision](../verification/automation-reporting/bounded-accounting.md) defines native evidence categories. A ticket has a hard maximum of262144 representation bytes,32 reserved provider-call permissions,10000 filesystem read and write operations and120000 milliseconds. A live ticket accepts at most128 callbacks. An absolute `attemptDeadline` can tighten the original120000-millisecond deadline. Continuations cannot renew it. Actual provider cancellation is not established. Each local window advances at most64 durable transitions. These cooperative bounds do not admit a fleet ticket or enforce provider-wide limits. The parent owns native admission and actual connector calls.

Accounting separates acquired and generated representations, actual filesystem bytes and operations, reserved provider permissions and known returned provider attempts. A pending reservation is unavailable allowance, not measured usage. Every actual source or private-state reread is acquired again. Persisting an already charged exact raw buffer once adds write traffic without another evidence representation. Accounting revision `native-evidence-v2-identical-utf8-once` treats canonical text and its identical UTF8 buffer as one logical representation. Internal metadata, decode buffers and transient diagnostic serialization have separate process counters. They do not add fleet evidence bytes. Base64 and new retained JSON frames remain distinct representations.

A live runtime reuses only already charged immutable buffers from the same ticket and exact prior ledger. A new ticket or process acquires those bytes again. The runtime does not cache the source tree or mutable assembly files. Reports retain original source clocks and explicit nulls. Capture starts at its declared start and ends when the full membership and metadata fence seals. An injected end clock requires the explicit synthetic flag.

Capture proceeds through census, first pass with immediate predecessor checks, deferred predecessor pairs, optional preceding-history comparison, second pass and final membership and metadata checks. Immutable indexed descriptors and exact raw shards survive process restarts. The final job checks every source identity and modification clock again before sealing. These observations establish temporal consistency under immutable producer-file assumptions. They do not establish an atomic filesystem snapshot or future latest state.

Publication stores one intent before each effect. Tool actions use a local `file_uri`. Raw download responses retain the original response object and a separate exact raw file. Per-object response cells replace whole-journal replay. Inventories assemble canonical fragments into a bounded durable file. Upload and pointer mutations are never blindly reissued. A missing read response requires an explicit known-ID refresh, which creates a new action and permission. Recovery binds an acquired exact upload ID and still requires metadata and raw readback.

Successors compare complete admitted history and audit predecessor generations incrementally. A retained late conflicting response writes the shared owner conflict record before any descendant can obtain a fresh dispatch permission. Historical failed read responses remain attached to their original actions when an explicit refresh succeeds. Pointer closure requires the exact desired raw readback.

The single-command CLI accepts `begin`, `advance`, `next`, `respond`, `recover` and `retry-read` with `--file ABSOLUTE_REQUEST`. The `live` command accepts JSON lines containing `action` and an absolute request `file`. Each line is bounded to4096 bytes. The process returns one JSON result per line and performs no provider calls.

Run `node --test test/automation-reporting-bounded.test.mjs` for focused controls. Run `node verification/automation-reporting/bounded-fixture.mjs PRIVATE_SHAPE_JSON` for frozen fail-before and new synthetic flight evidence. The optional shape contains only namespace names and individual file and byte totals. It never contains production record bodies. Run `node verification/automation-reporting/bounded-capacity.mjs REPORT_JSON AVAILABLE_SLOTS` for the separate capacity verdict. A failing capacity result exits3 and retains its evidence.

The status-only controller accepts `status` with exact launch and registered controller identity flags. It reads at most4096 bytes of claim metadata and grants no source execution. Its input and output are each separately bounded, with an8192-byte combined limit. Novel controller authorization still requires independent review.
